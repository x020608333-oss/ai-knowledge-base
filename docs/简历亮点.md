## 一、简历项目描述（可直接使用）

**AI 智能知识库问答平台（RAG）** | 独立开发 | Java / Spring Boot 3 / Spring AI / Ollama（本地大模型）

> 基于 RAG 架构的企业级智能问答后端，解决大模型知识截止与幻觉问题，支持私有文档的精准、可溯源问答。

**主要工作：**
- 设计并实现 RAG 全链路：文档解析 → 分块 → 向量化入库 → 语义检索 → Prompt 组装 → 流式生成 → 答案溯源；
- 基于 **Spring AI** 统一封装 ChatClient / EmbeddingModel / VectorStore，抽象出可切换任意 OpenAI 兼容模型（GPT / 通义千问 / DeepSeek / 本地 Ollama）的接入层；
- 采用 **SSE 流式输出**（Reactor Flux）实现打字机效果，将首字延迟降低至秒级，生成任务下沉独立线程池避免阻塞；
- 文档摄入采用 **异步 + 状态机**（PENDING/PROCESSING/COMPLETED/FAILED）处理，支持 PDF/DOCX/MD/TXT，单文件 50MB；
- 引入**相似度阈值过滤 + 强约束 Prompt** 双管齐下抑制幻觉，回答附带引用来源（文件名 + 片段 + 相似度）实现可溯源；
- 使用 Caffeine 本地缓存热点问答（可平滑升级 Redis 分布式缓存），MyBatis-Plus 持久化会话与消息，支持多轮上下文记忆。

**量化指标（按真实数据填写，示例）：**
- 知识库可稳定支撑 X 份文档、Y 万向量切片；
- 检索命中率 Z%，问答可溯源率 100%；
- 首字延迟 < 1s，异步解析吞吐 X 文档/分钟。

## 二、高频面试问题 & 回答要点

### Q1：什么是 RAG？为什么用它而不是直接微调？
- **RAG**：检索增强生成。提问时先从知识库检索相关片段，作为上下文交给 LLM 生成，从而注入私域/最新知识。
- **对比微调**：微调改"能力/风格"，不改"事实"；RAG 可动态更新、可溯源、成本低、抗幻觉。两者互补。

### Q2：你们的文档是怎么切分的？切多大？
- 用 `TokenTextSplitter`，按 token 切并保留重叠（overlap），避免语义在边界截断。
- 权衡：太大→检索不精、浪费上下文；太小→语义残缺、噪声多。需按业务调参，并可用"语义/结构化切分"进一步优化。

### Q3：怎么保证回答不"胡说八道"（幻觉）？
- 三层防线：① Prompt 强约束"只能基于参考资料"；② 相似度阈值过滤，无相关内容就明确说"查不到"；③ 低温度 + 强制标注引用来源，便于核验。

### Q4：向量检索和关键词检索有什么区别？能结合吗？
- 向量检索基于语义相似度，擅长同义改写；关键词（BM25）擅长精确匹配专有名词。
- 可做**混合检索**：两路召回后融合，再用 Rerank 精排，显著提升召回质量（项目可扩展点）。

### Q5：SSE 流式是怎么实现的？为什么不用 WebSocket？
- 后端返回 `text/event-stream`，用 Reactor `Flux` 逐段推送；前端用 `fetch` 读取流（EventSource 不支持 POST）。
- SSE 是**单向、轻量、基于 HTTP**，适合"服务端→客户端"的流式推送；WebSocket 是**全双工**，适合强交互场景。本场景单向足够，SSE 更简单。

### Q6：大文件上传解析很慢，怎么保证接口不卡？
- 上传接口**立即返回**，解析/向量化用 `@Async` 下沉独立线程池异步处理，配合状态机追踪进度。
- 拒绝策略用 `CallerRunsPolicy` 做背压，防止任务堆积导致 OOM。

### Q7：多轮对话是怎么记住上下文的？
- 会话/消息落库，每次取最近 N 条构建 messages 传入模型。
- 进阶：问题改写（Query Rewrite）解决"它/这个"指代消解；上下文过长时做摘要压缩。

### Q8：这个项目有哪些可以继续优化的点？（体现思考深度）
- 混合检索 + Rerank；语义缓存降本；多知识库 metadata 隔离；接入 Langfuse 做可观测与效果评估；演进为支持工具调用的 Agent。
